# AgileFast Web 前端页面开发规范

## 1. 适用范围

本文适用于 `apps/ylfast-iot-platform` 的业务列表页、CRUD 页面和卡片/表格混合页面开发。

主要参考以下真实示例：

- `apps/ylfast-iot-platform/src/views/iot/plugin/index.vue`
- `apps/ylfast-iot-platform/src/views/iot/plugin/data.tsx`
- `apps/ylfast-iot-platform/src/views/iot/plugin/components/PluginCard.vue`
- `apps/ylfast-iot-platform/src/views/iot/plugin/index.vue`

## 2. 页面目录结构规范

标准资源页面建议按如下结构组织：

```text
src/views/{domain}/{page}/
├─ index.vue
├─ data.tsx
└─ components/
   ├─ XxxCard.vue
   ├─ XxxForm.vue
   └─ XxxDrawer.vue
```

职责划分：

- `index.vue` 负责页面编排、查询参数组装、弹窗打开、提交、删除、批量操作等页面级逻辑。
- `data.tsx` 负责表格列、搜索 schema、编辑表单 schema、展示映射和 formatter。
- `components/` 负责卡片、详情块、复杂子组件。

不要把所有逻辑都堆到 `index.vue`。

## 3. 国际化规范

业务页面、`data.tsx`、表单 schema、表格列标题、按钮文案等涉及文案时，统一使用：

```ts
import { $t } from '@vben/locales';
```

要求：

- 不要在业务页面里大量硬编码中文文案。
- 页面标题、按钮文案、表格列标题、状态文案、弹窗标题优先走国际化。
- 同一资源的国际化按单一职责拆分，不要继续把无关页面文案混入同一个语言文件。

当前工程的国际化目录为：

```text
src/locales/langs/{语言}/
```

新增资源时，按资源单独创建语言文件，例如文章资源：

```text
src/locales/langs/zh-CN/article.json
src/locales/langs/en-US/article.json
```

约束：

- `Article` 页面相关的国际化统一放在 `article.json`。
- 不要把文章页面文案继续堆进 `examples.json`、`system.json` 这类大文件。
- 资源文件命名统一使用小写英文资源名，如 `article.json`、`device.json`、`receipt.json`。

国际化键组织规则：

- 国际化文件采用“文件名分域”的方式加载，例如 `article.json` 对应访问前缀 `article`。
- 文件内容内部必须保持平铺结构，不要再嵌套一层同名根节点。
- 例如在 `article.json` 中应直接定义 `title`、`actions.add`、`fields.title`。
- 页面访问方式统一写成 `$t('article.title')`、`$t('article.actions.add')`。
- 不要写成 `article.json -> { "article": { ... } }`，否则实际访问路径会变成 `article.article.xxx`。

正确示例：

```json
{
  "title": "文章",
  "actions": {
    "add": "新增文章"
  },
  "fields": {
    "title": "文章标题"
  }
}
```

错误示例：

```json
{
  "article": {
    "title": "文章"
  }
}
```

## 4. 图标规范

业务页面图标统一使用 `Iconify`，创建方式统一为：

```ts
import { createIconifyIcon } from '@vben/icons';

const TrashIcon = createIconifyIcon('lucide:trash-2');
```

要求：

- 不要在同一页面混用多套图标创建方式。
- 同一页面用到的图标统一在脚本顶部集中声明。
- 优先选择语义清晰、风格一致的图标集，当前示例优先使用 `lucide`。

示例：

```ts
const EditIcon = createIconifyIcon('lucide:edit-3');
const TrashIcon = createIconifyIcon('lucide:trash-2');
const PlusIcon = createIconifyIcon('lucide:plus');
```

## 5. 枚举规范

业务页面或接口中复用的枚举，统一收敛到：

```text
src/enums/
```

适用范围：

- 状态枚举
- 类型枚举
- 操作模式枚举
- 标签颜色映射

要求：

- 不要把同一套枚举值在多个 `api`、`data.tsx`、`vue` 文件里重复定义。
- 如果某个枚举会被多个页面或多个模块复用，必须抽到 `enums/`。
- 页面本地仅保留与展示强绑定且不会复用的临时映射。

这里的“枚举”不仅指 TypeScript `enum`，也包括常量对象方式，两种都允许：

```ts
export enum ArticleStatus {
  Draft = 0,
  Published = 1,
}
```

```ts
export const ARTICLE_STATUS = {
  ENABLE: '1',
  DISABLED: '2',
} as const;
```

适用建议：

- 需要明确枚举成员语义、适合做类型约束时，优先用 `enum`。
- 需要与后端字符串值直接对齐、便于序列化和映射时，可以用 `const` 常量对象。
- 同一业务域内保持一种主风格，不要同一个状态值一会儿用 `enum`，一会儿又定义一套重复常量。

## 6. 页面路由规范

页面路由默认不要由前端自行新增静态路由，一般由后端统一配置并下发。

要求：

- 不要为了新增一个业务页面，直接在前端路由模块里手工新增静态业务路由。
- 前端页面开发优先遵循后端菜单/路由配置结果。
- 前端只负责按约定路径提供页面组件，不再维护一套独立的业务路由真相源。

特殊约定：

- `demo` 页面允许前端静态路由创建。
- 登录页、404、框架演示页等基础路由可以保留前端静态路由。
- 真实业务菜单和业务页面入口，默认以后端配置为准。

## 7. CRUD 页面首选模式

对于标准列表页或卡片页，优先使用：

- `useYlVxeTableCard`
- `useVbenForm`
- `useVbenModal`

适合场景：

- 表格 + 卡片切换
- 条件搜索
- 弹窗新增/编辑
- 单条删除 / 批量删除

## 8. `index.vue` 职责规范

`index.vue` 统一负责以下内容：

1. 初始化表单与弹窗
2. 组装查询参数
3. 定义新增、编辑、删除、批量删除动作
4. 连接 `TableCard`、`Modal`、`Form`

推荐骨架：

```vue
<script setup lang="ts">
const [Form, formApi] = useVbenForm({ schema: formSchemas });
const [Modal, modalApi] = useVbenModal({ onConfirm: async () => {} });
const [TableCard, gridApi] = useYlVxeTableCard({
  gridOptions: {
    columns,
    proxyConfig: {
      ajax: { query: gridQuery },
    },
  },
});
</script>
```

## 9. `data.tsx` 职责规范

`data.tsx` 统一收敛：

- `searchFormSchemas`
- `columns`
- `formSchemas`
- 页面级显示映射方法

例如：

- 状态 `options`
- 状态 `label` 映射
- 表格 formatter

这样可以避免：

- `index.vue` 体积膨胀
- 表格列和表单配置分散
- 同一个字段在多个文件里重复定义

## 10. 搜索区规范

### 10.1 统一使用 `YlDcFormSchema`

搜索区优先使用 `yl-dc-form`，对接 `QueryParamEntity.terms`。

示例：

```ts
export const searchFormSchemas: YlDcFormSchema[] = [
  {
    component: 'Input',
    field: 'title',
    label: '文章标题',
    termTypes: ['like', 'eq'],
  },
];
```

### 10.2 搜索字段选择原则

优先放这些字段：

- 资源标题/名称
- 分类
- 状态
- 编码/编号
- 负责人

不要把所有字段都堆到搜索区。

## 11. 表格区规范

### 11.1 列配置规范

表格列推荐至少包含：

- 主键或业务编码
- 资源名称/标题
- 核心业务字段
- 状态
- 创建时间
- 操作列

### 11.2 批量操作前提

如果页面需要批量删除、批量启停、批量导出，表格必须补复选框列：

```ts
{
  align: 'center',
  type: 'checkbox',
  width: 56,
}
```

### 11.3 分页响应规范

`useYlVxeTableCard` 默认消费：

- `items`
- `total`

因此 `proxyConfig.response` 应保持为：

```ts
response: {
  result: 'result',
  total: 'total',
}
```

不要误写成 `data`。

## 12. 表单规范

### 12.1 表单字段范围

编辑表单只放可编辑的业务字段。

一般不放：

- `creatorId`
- `creatorName`
- `createTime`
- `modifierId`
- `modifierName`
- `modifyTime`

这些审计字段优先在列表或详情中展示，不放到弹窗表单里编辑。

### 12.2 常见字段组件建议

| 字段类型  | 推荐组件                |
| --------- | ----------------------- |
| 文本      | `Input`                 |
| 长文本    | `Textarea`              |
| 数值/排序 | `InputNumber`           |
| 状态枚举  | `RadioGroup` / `Select` |
| 远程字典  | `ApiSelect`             |

### 12.2.1 后端字典获取规范

页面或组件需要获取后端字典项时，默认复用：

```text
apps/ylfast-iot-platform/src/hooks/dictionary/useDictionary.ts
```

推荐方式：

```ts
const { getDictItem } = useDict('device-log-type');
```

要求：

- 不要在页面里重复手写字典接口请求逻辑
- 不要同一个字典在多个页面各自封装重复获取函数
- 如果只是读取某个字典项列表，优先使用 `useDict('dict-id')`
- 页面中涉及状态、类型、下拉选项等后端字典时，优先通过该 hook 获取并复用结果

### 12.3 默认值规范

新增时需要默认值的字段，应在打开弹窗时设置：

```ts
formApi.setValues({
  sort: 0,
  status: 1,
});
```

不要依赖用户手工输入所有默认字段。

## 13. 弹窗交互规范

推荐把弹窗打开动作封装成一个方法：

```ts
function openModal(type: 'add' | 'edit', row?: Entity) {}
```

统一在这里做：

- 表单重置
- 回填
- 默认值设置
- 标题设置

不要把新增和编辑逻辑分散在多个函数里重复写。

## 14. 卡片组件规范

如果页面支持卡片模式，卡片组件建议单独拆到 `components/` 下。

卡片应重点展示：

- 主标题
- 核心标签
- 内容摘要
- 状态
- 时间/排序等辅助信息

不要像早期 demo 一样直接 `{{ row }}` 输出整个对象。

## 15. 字段同步规范

后端字段变更后，前端至少同步修改以下位置：

1. `src/api/...` 中的实体接口
2. `views/.../data.tsx` 中的表格和表单 schema
3. `views/.../components/*.vue` 中的展示组件
4. `src/locales/langs/.../*.json` 中的字段国际化
5. `src/enums/*.ts` 中的相关状态/类型枚举

## 16. 设备示例约定

当前 `crud-demo-device` 页面已对齐后端字段：

- `deviceName`
- `deviceStatus`
- `deviceLocation`
- `deviceAmount`

状态示例约定：

- `0`: 停用
- `1`: 启用

## 17. 禁止事项

- 不要在页面里残留不存在的字段。
- 不要把 API 类型定义、表格列、表单 schema 混在同一个大文件里。
- 不要在 `index.vue` 里直接写大段 JSX 或复杂格式化逻辑。
- 不要让卡片和表格展示两套字段长期不一致。
- 不要页面自己再发明一套分页返回结构。
- 不要在国际化资源文件里再嵌套同名根节点。

## 18. 当前推荐结论

后续开发新的前端 CRUD 页面时，统一采用以下模板：

- `api` 层：`namespace + basicCrudApis + 自定义接口`
- 页面层：`index.vue + data.tsx + components/`
- 国际化层：按资源拆分 `src/locales/langs/{lang}/{resource}.json`
- 枚举层：通用状态/类型统一放到 `src/enums/`
- 列表层：`useYlVxeTableCard`
- 表单层：`useVbenForm`
- 弹窗层：`useVbenModal`
- 查询层：`QueryParamEntity`

这套方式的优点是：

- 前后端字段映射关系清晰
- 页面结构稳定，便于复制为模板
- 国际化、枚举、图标、页面职责边界明确

## 19. 注释规范

前端开发时，必须补充必要注释，不能只依赖命名表达全部语义。

强制要求的注释范围：

- 接口方法：页面中的核心动作方法、接口封装中的自定义方法、复杂事件处理方法必须写注释
- 属性：前端类型定义中的关键属性必须写注释，尤其是 `api` 层接口类型、表单数据类型、卡片/表格展示类型
- 复杂逻辑：复杂状态流转、动态表单联动、表格响应映射、国际化兼容处理、格式化规则、权限控制逻辑必须写注释

具体要求：

- `src/api/**/*.ts` 中的接口类型属性应说明字段业务含义，不要只有字段名
- `data.tsx` 中的复杂 formatter、options 映射、联动逻辑应加注释说明
- `index.vue` 中的查询参数组装、保存逻辑、批量操作、弹窗回填等复杂流程应加注释
- `components/*.vue` 中存在计算属性组合、展示降级、兼容兜底时，应写清楚原因

禁止事项：

- 不要写“点击按钮”“调用接口”“设置数据”这类没有信息量的注释
- 不要把简单模板渲染全部写成重复性注释
- 不要出现关键复杂逻辑完全无注释的情况

推荐原则：

- 注释优先解释“为什么这样设计”以及“有哪些约束”
- 注释要和字段、逻辑、交互行为同步维护，不能长期失真

## 20. AI Agent 执行约束

- AI Agent 默认不执行后端编译、打包、启动等操作
- 后端模块的编译、打包、启动、联调验证统一由用户手动执行
- AI Agent 在完成后端代码修改后，只说明建议的验证方式，不主动运行 Maven、Gradle 等后端构建命令
- 前端是否执行安装、类型检查、构建、预览命令，可根据当前任务和用户要求另行判断

## 21. 前端页面生成风格约束

- 前端页面生成与样式调整时，默认不要使用渐变背景、渐变按钮、渐变描边
- 前端页面生成与样式调整时，默认不要使用大圆角卡片，卡片、弹窗、输入框、按钮等圆角保持克制
- 前端页面生成与样式调整时，默认不要使用过粗字重，标题、正文、按钮文字优先使用常规或中等字重
- 前端页面生成与样式调整时，`hover` 效果不要做位置偏移，不使用上移、横移、缩放抬升等跳动式反馈
- 前端页面生成与样式调整时，边框不要过粗，优先使用细边框；如果元素已经使用明显边框，就不要再叠加阴影
- 前端页面生成与样式调整时，颜色优先遵循当前系统主题色，不随意引入新的主色、副色体系
- 前端页面生成时，样式实现优先使用原子 CSS，尽量直接在模板中通过原子类完成布局、间距、颜色和边框表达
- 如无用户明确要求，不要生成偏装饰化、偏营销化的视觉风格，优先保持简洁、规整、耐用
